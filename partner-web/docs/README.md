# QUBAT EV — кабинет партнёра, WEB DEMO 0.1.0

Самостоятельный адаптивный кабинет на русском языке: мониторинг, точки и параметры, отчёты, финансы, доступы, бренды и журнал. Этап 1 технического задания от 1 ноября 2026 года. Данные синтетические, действия выполняются в браузере. Версия веб-демо `0.1.0` независима от Android-приложения QUBAT EV `1.8.0`; приложение водителя и его пять разделов этим проектом не изменяются.

## Запуск

Из корня этой папки:

```bash
python3 -m http.server 4173 --directory dist
```

Открыть `http://localhost:4173`. Для ES-модулей нужен HTTP-сервер: открытие `dist/index.html` через `file://` не поддерживается. Сборка и установка npm-зависимостей не требуются. Сервер Python раздаёт статические файлы; API, базы данных и серверной авторизации здесь нет.

Проверки логики:

```bash
node --test tests/*.test.mjs
```

## Что можно проверить

- Открыть мониторинг и сравнить число аппаратов с числом разъёмов. Устаревшая телеметрия должна отображаться отдельно от свежего состояния станции.
- Выбрать демонстрационный профиль и организацию; сравнить доступные точки, финансовые разделы и действия. Выбор профиля имитирует роль, а не выполняет вход.
- Изменить параметры доступной точки, просмотреть историю, создать новую версию тарифа. Завершённые сессии сохраняют использованную версию тарифа.
- Задать период и фильтры отчёта. Выгрузить `.xlsx` с листами «Сводка», «Сессии», «По станциям», «Платежи», «Расходы»; сравнить строки и суммы с текущим отчётом.
- Сравнить расчётные расходы с фактическим счётом месяца. Ввод счёта не удаляет расчёт электричества.
- Проверить ограниченную роль: отсутствие кнопки дополнено проверкой разрешения в локальном репозитории, включая обращение по ID.

Все суммы и изменения относятся только к демо. Платежи, OTP/2FA, приглашения по телефону/email, загрузка настоящих квитанций, OCPP и команды живому оборудованию не подключены.

## Состояние браузера и профили

Демонстрационный профиль выбирается через имя аккаунта внизу боковой панели или кнопку аккаунта справа вверху → «Демонстрационные роли». Это инструмент проверки сценариев владельца, сотрудника, бухгалтера, наблюдателя и суперадминистратора. Переключение не подтверждает личность. Состояние хранится локально для текущего origin браузера; другой браузер, режим инкогнито или другой порт имеют отдельное хранилище. Экспорт создаётся локально из доступной выбранному профилю выборки.

В окне ролей «Восстановить тестовые данные» → «Восстановить» возвращает исходный набор и очищает локальные правки/аудит. Перед сбросом сохраните нужные демонстрационные выгрузки. Очистка данных сайта в настройках браузера также удаляет локальные правки. Не вводите персональные сведения, пароли, реальные счета и ключи операторов.

Веб-оболочка создаёт исходные данные относительно даты первого запуска в `Asia/Bishkek`; повторное открытие использует сохранённый срез. Данные не приходят от станций. «Обновить» перерисовывает локальный срез, а восстановление пересоздаёт тестовые данные. Даты/фильтры интерфейса можно менять без изменения исходных сессий.

Локальный ключ набора/выбранного профиля — `qubat-partner-web-demo-v1`, темы — `qubat-partner-theme`. Имя ключа хранилища не равно версии схемы данных. Период и фильтры экрана устанавливаются заново при открытии; сохранённые сессии, изменения и аудит остаются в наборе до сброса.

Профиль владельца видит свою организацию; сотрудник и наблюдатель ограничены назначенными станциями; бухгалтер получает финансовые права назначенной организации без управления зарядкой. Полный перечень тестовых ID и программный интерфейс приведены в [API.md](API.md).

## Структура и граница безопасности

`dist/` содержит готовые статические ES-модули и стили. `tests/` содержит автоматические проверки бизнес-логики. `docs/API.md` описывает локальную модель и проектируемый сервер; `docs/openapi.yaml` — **проект контракта, сервер по нему не реализован**; `docs/ROADMAP.md` — зависимости и этапы реальной интеграции.

Репозиторий демо проверяет роли, организацию и назначенные станции при чтении и изменении данных. Это позволяет проверять интерфейс и правила, но **не является серверной авторизацией**: исходные тестовые данные и код доступны пользователю браузера, `localStorage` можно менять. Для реальных данных сервер должен заново проверять пользователя, организацию, станции и разрешение на каждом запросе, экспорте, скачивании, обращении по прямому ID и чтении истории.

Настоящий backend, подтверждение личности, 2FA, хранилище вложений, фоновые задачи и интеграции подключаются отдельными этапами. Наличие прототипа API не означает, что у Charge24, Spark, Pay24, EEJANN или другого оператора есть открытый API либо выдано разрешение на подключение.

Публикация через ChatGPT Sites предназначена для владельца сайта с частным доступом. Это ограничение доступа к опубликованному демо; оно не заменяет будущую бизнес-авторизацию. Исходники выпускаются в отдельной GitHub-ветке и Pull Request. Основная ветка и боевые настройки не меняются в рамках этапа 1.

## Финансовые соглашения

Валюта — KGS. Денежные вычисления используют точное представление; денежные строки API имеют фиксированные два десятичных знака, ставки и энергия имеют отдельную точность. Двоичная арифметика `Number` не должна определять реальные расчёты. Периоды отчётов трактуются в `Asia/Bishkek`; дата конца в интерфейсе включается полностью, на сервере ей соответствует исключающая верхняя граница следующего дня.

Оплаченная выручка, начисления, возвраты, комиссии, налоги, аренда, электричество и выплаты показываются отдельно. Тарифы и финансовые условия имеют версии и даты действия. Неоплаченная сессия не становится оплаченной выручкой. Изменение условий не пересчитывает закрытые периоды без отдельной корректировки с аудитом.

Подробные правила, будущие ограничения и вопросы к операторам приведены в [API.md](API.md) и [ROADMAP.md](ROADMAP.md).

## Проверка в браузере

Для дополнительного сценария `python3 tests/browser_smoke.py` нужен запущенный сервер на 4173, Python Playwright, Chromium (`/usr/bin/chromium`) и openpyxl. Эти инструменты используются только для разработки и не являются зависимостями сайта. Сценарий проверяет сохранение, историю тарифов, XLSX, квитанции, роли, отзыв доступа, мобильный экран и обе темы. Снимки записываются в игнорируемый каталог `work/browser-checks/`.

Выручка на графике агрегируется по началу сессии (Asia/Bishkek) и совпадает с суммой оплаченных сессий за вычетом возвратов. При неполных платёжных данных график показывает отсутствие данных. В финансах кнопка «Статьи расчёта» задаёт вычеты; денежный перевод партнёру по умолчанию показывается отдельно от расходов.
